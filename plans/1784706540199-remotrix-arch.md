# Remotrix — Rust 原生下载管理器 (Motrix 风格)

## 1. 项目概述

基于 Rust + `aria2-core` 的现代桌面下载管理器，UI 参考 Motrix.app 设计。

| 组件 | 选型 |
|---|---|
| 下载引擎 | `aria2-core` 0.2.3 (tokio async) |
| GUI 框架 | `iced` 0.13+ (纯 Rust 渲染) |
| 异步运行时 | tokio (GUI side-channel 模式) |
| 图标 | 自定义 "R" 菱形图标（设计需求见第 9 节） |

---

## 3. 架构设计

### 3.1 双层事件循环

iced 主循环与 aria2-core 的 tokio 引擎通过 `mpsc` 通道通信：

```
┌─────────────────────────────────────────┐
│              iced UI Loop                │
│  ┌────────┐ ┌──────────┐ ┌──────────┐  │
│  │Sidebar │ │ TaskList │ │Settings/ │  │
│  │        │ │          │ │ AddDialog│  │
│  └───┬────┘ └────┬─────┘ └─────┬────┘  │
│      │           │              │       │
│      └───────────┼──────────────┘       │
│                  ▼                      │
│           update(Message)               │
│           │            ▲                │
│           ▼            │                │
│    Command/Subscription│                │
└───────────┼────────────┼────────────────┘
            │ mpsc::Sender  │ mpsc::Receiver
            ▼               │
┌───────────────────────────┴────────────┐
│          Tokio Runtime                  │
│  ┌─────────────────────────────────┐   │
│  │  EngineBridge                    │   │
│  │  ├─ RequestGroupMan (任务管理)   │   │
│  │  └─ DownloadEngine (事件循环)    │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 3.2 通道协议

```rust
// GUI → 引擎指令
enum EngineCmd {
    AddDownload { urls: Vec<String>, options: DownloadOptions, save_dir: PathBuf },
    Pause(String),
    Resume(String),
    Remove(String),
    SetOption(String, String),
    Shutdown,
}

// 引擎 → GUI 事件 (iced Subscription 消费)
enum EngineEvent {
    Progress { gid: String, downloaded: u64, total: u64, speed: u64, status: String },
    Complete(String),
    Error(String, String),
    Added(String),
    Removed(String),
    EngineReady,
    EngineStopped,
}
```

### 3.3 iced 集成方式

| 场景 | 实现 |
|---|---|
| 单次操作 (新增/暂停) | `iced::Command::run` 通过 Sender 发送 EngineCmd |
| 持续进度更新 | `iced::Subscription::run` 在 Receiver 端 poll EngineEvent |
| 引擎生命周期 | `main.rs` 中 `tokio::spawn` engine 任务，句柄存入 App State |

## 6. 实现步骤

### Phase 1: 脚手架 + 引擎集成
1. 初始化 Rust workspace，添加 `aria2-core` 依赖
2. 实现 `EngineBridge`：tokio runtime 上运行 aria2-core event loop
3. 实现通道协议 (EngineCmd / EngineEvent)
4. 编写集成测试：引擎启动/停止/新增下载

### Phase 2: 核心 UI (iced)
5. 创建 iced Application 骨架 (main.rs + app.rs)
6. 实现 `theme.rs`：Motrix 暗色主题 Palette
7. 实现 `sidebar.rs`：左侧导航 + 路由切换
8. 实现 `task_list.rs`：任务卡片列表（含进度条）
9. 实现 `add_dialog.rs`：新建任务弹窗
10. 实现 `settings_page.rs`：设置页面

### Phase 3: 桥接联动
11. 实现 `Subscription`：从 EngineEvent Receiver 拉取进度
12. 实现 `Command`：用户操作 → EngineCmd → aria2-core
13. 状态同步：任务增/删/暂停/恢复全部走通道
14. 配置持久化：保存/加载设置 (dir, limits)

### Phase 4: 打磨
15. 应用图标装配
16. Torrent 文件选择器 (rfd 原生对话框)
17. 国际化 (中文/英文)
18. 性能优化 (虚拟列表)

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| iced tokio feature 不成熟 | 回退到手动 `Runtime::block_on` |
| aria2-core API 不稳定 | lock 版本号，wrapper 层隔离 |
| 大型任务列表性能 | `scrollable` + 分页渲染 |
| 系统托盘不支持 | 先用 `tray-icon` 或暂不实现 |
